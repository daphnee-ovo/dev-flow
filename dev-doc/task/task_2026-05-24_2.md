- [x] T3：devtest.md 改为双重 Review（Spec Compliance + Code Quality）
  - level: P0
  - model: capable
  - details：重写 `commands/devtest.md` 的 Agent 调度部分，从单轮 QA 改为串行双轮：Round 1 Spec Compliance（逐条对照 Done when + SPEC 接口/格式验证，不评价代码质量）；Round 2 Code Quality（可读性/可维护性/性能/安全四维评估，PASS/WARN/FAIL 三级）。定义综合判定逻辑：两轮均 PASS → DONE；R1 FAIL → BLOCKED 写 issue；R1 PASS + R2 FAIL → 写 issue；R2 仅 WARN → DONE_WITH_CONCERNS。保留测试代码写入 tests/ 的要求。
  - depends on：无
  - Done when：`grep -c "Round 1\|Round 2\|Spec Compliance\|Code Quality" commands/devtest.md` >= 4；`grep "DONE_WITH_CONCERNS\|BLOCKED\|NEEDS_CONTEXT" commands/devtest.md | wc -l` >= 3；文件中包含两段独立的 agent prompt 模板

- [x] T4：devtest.md 增加 Subagent 状态返回协议
  - level: P0
  - model: standard
  - details：在 `commands/devtest.md` 中定义 subagent 输出格式约束——必须在结尾输出 STATUS 行（DONE / DONE_WITH_CONCERNS / NEEDS_CONTEXT / BLOCKED）+ 可选 DETAIL。定义 controller 收到各状态后的行为：DONE → 继续；DONE_WITH_CONCERNS → 写 issue 后继续；NEEDS_CONTEXT → 停顿向用户请求；BLOCKED → 停顿写 issue。无 STATUS 行 = DONE（向后兼容）。
  - depends on：T3
  - Done when：`grep "^STATUS:" commands/devtest.md || grep "STATUS: DONE" commands/devtest.md` 有输出；`grep -c "DONE\|DONE_WITH_CONCERNS\|NEEDS_CONTEXT\|BLOCKED" commands/devtest.md` >= 8（协议定义 + 行为描述）

- [x] T5：devtest.md 增加连续执行模式（--continuous / --step）
  - level: P1
  - model: standard
  - details：在 `commands/devtest.md` 中增加命令接口部分：`/devtest --continuous` 切换 STATUS.yaml 的 exec_mode 为 continuous 并启动连续推进；`/devtest --step` 切回逐步模式。定义连续推进的 Controller 逻辑：DONE → 自动推进下一个未完成 task；DONE_WITH_CONCERNS → 写 issue 后继续；NEEDS_CONTEXT → 停顿；BLOCKED → 停顿；所有 task 完成 → 停顿提示 /test。同步修改 `scripts/hooks/post-write.sh` 中的 devtest 触发提示，在 continuous 模式下提示为"自动推进下一个任务"而非"执行 /devtest"。
  - depends on：T2, T4
  - Done when：`grep "\-\-continuous\|\-\-step" commands/devtest.md | wc -l` >= 2；`grep "exec_mode" commands/devtest.md | wc -l` >= 1；`grep -c "continuous" scripts/hooks/post-write.sh` >= 1
