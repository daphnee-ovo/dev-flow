# DEV-TEST — 例行测试（任务级）

## 前置检查

1. 确认 STATUS 为 DEV
2. 确认 TASK.md 中有已勾选 `[x]` 的任务

## 触发时机

- 每完成一个任务后**必须**执行（hooks 会强制提醒）
- STATUS 保持 DEV，不切换阶段

## Agent 调度（强制模板）

**启动轻量独立 TEST subagent，范围限定为单个任务：**

```
Agent({
  description: "例行 TEST - 验证任务 <任务名>",
  prompt: `你是一名 QA 工程师。验证以下任务是否真正完成。

## 验证目标

任务：<从 TASK.md 摘取刚完成的任务名>
Done when：<该任务的 Done when 标准，原文>

## 相关规范

<仅从 SPEC.md 中摘取与该任务相关的部分，如接口定义、数据模型>

## 验证要求

1. 必须实际运行代码验证（启动服务/打开页面/执行命令）
2. 按 Done when 逐条检查
3. 只验证这一个任务，不扩大范围

## 输出格式

结论：通过 / 未通过
原因：<如果未通过，精确描述问题和复现步骤>

## 禁止

- 不要阅读 dev-doc/session/ 下的文件
- 不要验证其他任务
- 不要建议新功能
- 不要因为 SPEC 没要求的功能缺失而报"未通过"`
})
```

## 输入隔离规则

| 允许传入 | 禁止传入 |
|----------|----------|
| 该任务的描述和 Done when | 其他任务的信息 |
| SPEC.md 中相关部分（非全文） | 开发过程对话历史 |
| | session/memory/ 记录 |
| | PRD.md |

## 结果处理

- **通过** → 保持 TASK.md 的 `[x]`，继续下一个任务
- **未通过** → 取消勾选（改回 `[ ]`），报告问题，修复后重新 /dev-test

## 为什么需要独立 agent

开发者会无意识避开自己代码的薄弱点。即使是轻量测试，也必须由独立视角验证。"我检查过了没问题"不算验证。
